P0 核心必备功能
1. 本地Markdown知识库存储与浏览
维度	内容
功能描述	以本地文件夹为存储介质，用户可自由创建、编辑、浏览Markdown笔记，支持[[双向链接]]语法和YAML Frontmatter元数据
技术实现	直接使用本地文件系统作为存储层。前后端分离架构中，后端通过文件路径读写.md文件，前端展示笔记列表和内容
推荐技术栈	watchdog (Python文件监听库) + markdown (Python解析库)
可行性	✅ 极其成熟，无技术风险
2. 增量知识图谱自动构建
维度	内容
功能描述	新笔记加入时，自动提取实体和关系，更新图谱。只处理增量部分，不重建全库
技术实现	使用 itext2kg Python包。其核心模块包括：DocumentDistiller（用LLM将文档重写为语义块）→ IncrementalEntityExtractor（用余弦相似度匹配全局实体，去重）→ IncrementalRelationExtractor（抽取实体间关系）→ Neo4j集成。增量更新时，新实体通过向量相似度与已有实体匹配，相同概念自动合并，避免"节点膨胀"
推荐技术栈	itext2kg (pip安装) + Neo4j (社区版) + Langchain JSON Parser
可行性	✅ 已有完整学术论文和开源实现，WISE 2024接收论文
3. 向量检索（语义搜索）
维度	内容
功能描述	用户输入自然语言查询，返回语义最相关的笔记片段
技术实现	使用FAISS本地向量索引。笔记分块后通过Embedding模型生成向量，存入FAISS索引。查询时调用index.search()返回Top-K相似块。SecondBrain项目已验证了FAISS + nomic-embed-text的组合可行性
推荐技术栈	FAISS (Meta开源) + BAAI/bge-m3 / nomic-embed-text (通过Ollama或sentence-transformers加载)
可行性	✅ 极其成熟，工业级应用
4. 混合检索（向量 + 图谱）
维度	内容
功能描述	同时利用向量检索（找语义相关）和图谱检索（找关系相关），融合后生成答案
技术实现	Coordinator Agent模式：用户问题进入后，Agent判断意图，并行触发多路检索。向量检索召回语义相关片段，图谱检索用Cypher执行多跳查询。结果经RRF融合和cross-encoder重排序后交给LLM生成答案。SecondBrain项目完整实现了此架构，并提供了Recall@K、MRR@K等量化指标
推荐技术栈	LangGraph (Agent编排) + Neo4j (Cypher查询) + BGE-reranker-v2-m3 (重排序)
可行性	✅ 已有完整开源参考，可直接借鉴架构
5. 增量更新与自动同步
维度	内容
功能描述	监控笔记文件夹变更（新增/修改/删除），自动同步更新向量库和图谱，无需手动重建
技术实现	双机制保障：(1) 事件驱动：用watchdog监听OS文件系统事件，实时响应变更；(2) 定期轮询：作为兜底，定时扫描文件夹比对状态。变更进入增量更新引擎后，先检查内容哈希，若内容未变则跳过；若确实变更，只处理变更的文档——重向量化、更新图谱、删除对应节点。flexible-graphrag项目已有生产级实现
推荐技术栈	watchdog (文件监听) + PostgreSQL (存储同步状态、内容哈希)
可行性	✅ 生产级方案，flexible-graphrag已验证
6. LLM驱动的智能问答
维度	内容
功能描述	用户提问，系统通过混合检索召回上下文，由LLM生成答案，附引用来源
技术实现	混合检索结果 → 构建上下文 → 调用LLM (Ollama本地运行) → 流式输出 (SSE)。引用溯源：每个答案关联文档ID和段落位置，前端可点击跳转。SecondBrain项目实现了完整的证据卡片机制，答案可追溯
推荐技术栈	FastAPI + SSE (流式响应) + Ollama (Qwen/Llama)
可行性	✅ 非常成熟
P1 重要进阶功能
7. AI自动整理与知识清单生成
维度	内容
功能描述	用户选中一批笔记，LLM自动生成分类索引、主题摘要、知识清单
技术实现	调用LLM对选中的笔记批量处理，按用户指定的维度（时间、主题、标签等）自动归类，生成Markdown格式的索引页面。逻辑可参考SecondBrain的健康审计模块
推荐技术栈	自定义Prompt + Ollama
可行性	⚠️ 需自行设计Prompt和业务逻辑，技术无难点
8. 基于知识图谱的学习规划
维度	内容
功能描述	用户设定学习目标，系统分析当前知识库覆盖度，推荐需补充的知识点
技术实现	目标关键词 → 从Neo4j查询相关实体及关联度 → 识别知识盲区 → LLM生成学习路线图。可借鉴知识图谱社区检测（Leiden算法）识别知识簇，判断覆盖情况
推荐技术栈	Neo4j Cypher查询 + Leiden算法 + LLM
可行性	⚠️ 产品逻辑需自行设计，底层技术成熟
9. 周期性回顾摘要（周记/月报）
维度	内容
功能描述	定期（手动触发或定时）调用LLM，将近期笔记压缩成"回顾摘要"存储
技术实现	按时间筛选近期笔记 → 拼接上下文 → LLM生成摘要 → 作为新笔记存入知识库（带特殊标签如#weekly-review）
推荐技术栈	定时任务（APScheduler）+ Ollama
可行性	⚠️ 需自行设计调度和存储逻辑
10. 知识健康检查
维度	内容
功能描述	检测图谱中的孤立节点、陈旧信息、缺失交叉引用，主动提示用户
技术实现	Cypher查询检测入度为0的节点；内容哈希对比检测过时信息；检查笔记中的[[]]是否在库中存在对应文件。SecondBrain的GET /maintenance/health接口已实现类似功能
推荐技术栈	Neo4j Cypher + Python脚本
可行性	✅ 技术成熟，可借鉴现有实现
11. 知识图谱可视化展示
维度	内容
功能描述	前端以节点-边网络图展示知识图谱，用户可点击节点查看关联笔记
技术实现	后端从Neo4j查询图谱数据（节点+边），返回JSON给前端，前端用Cytoscape.js渲染交互式网络图
推荐技术栈	Cytoscape.js (前端) + Neo4j REST API
可行性	✅ 非常成熟
P2 可选加分功能
12. 多格式文档导入（PDF/网页剪藏）
维度	内容
功能描述	支持导入PDF、网页内容，自动转为Markdown后入库
技术实现	PDF用pypdf/pypdfium2解析；网页用html2text或trafilatura提取正文。SecondBrain项目验证了PDF和Web Processor的可行性
推荐技术栈	pypdf + html2text
可行性	✅ 技术成熟
13. 内置Markdown编辑器
维度	内容
功能描述	在Web界面内直接编辑笔记，无需外部编辑器
技术实现	使用开源Markdown编辑器组件（如Milkdown、Vditor），支持实时预览、双链补全
推荐技术栈	Milkdown / Vditor (React组件)
可行性	✅ 非常成熟
🛠️ 综合技术栈总结
层级	推荐方案	说明
后端框架	Python 3.10+ / FastAPI	RAG生态最成熟
图数据库	Neo4j (社区版)	GraphRAG标准选型
向量数据库	FAISS (本地轻量) 或 Qdrant (功能更全)	个人项目推荐FAISS，零运维
增量图谱构建	itext2kg	核心依赖，专门解决增量更新
增量同步框架	flexible-graphrag 增量更新引擎	可选，提供完整的事件驱动+轮询双机制
文档解析	pypdf / markdown / html2text	多格式支持
Embedding模型	BAAI/bge-m3 (通过Ollama)	本地运行
LLM推理	Ollama + Qwen/Llama	完全本地、免费
重排序	BGE-reranker-v2-m3	提升检索准确率
前端框架	React + TypeScript + Vite	成熟生态
图谱可视化	Cytoscape.js	交互式网络图
Markdown编辑器	Milkdown / Vditor	可选
